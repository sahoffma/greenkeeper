## Entscheidung

### Area (Rasenfläche)

Eigenständige fachliche Einheit mit eigenen Stammdaten, optionaler Größe, Historie, Maßnahmen und Zustand.

**Technisch:** Tabelle `areas` (bestehend).

### CareGroup (Pflegegruppe)

Beschreibt, welche Rasenflächen im Alltag **zusammen angesprochen** werden.

**Technisch:** Tabelle `care_groups` mit `user_id`, `name`, `sort_order`, `archived_at`.

### CareGroupArea (Zuordnung)

Verknüpft genau **eine** Rasenfläche mit **einer** Pflegegruppe.

**Technisch:** Tabelle `care_group_areas` mit Unique-Constraint auf `area_id`.

### Kardinalitäten

| Beziehung | Regel (aktuelle Ausbaustufe) |
|-----------|------------------------------|
| Nutzer → Flächen | 1 : n |
| Nutzer → Pflegegruppen | 1 : n |
| Pflegegruppe → Flächen | 1 : n |
| Fläche → Pflegegruppe | **1 : 1** (Unique auf `area_id`) |

### Onboarding-Eingabe vs. Domänenmodell

| Onboarding | Domäne |
|------------|--------|
| `together` | eine Pflegegruppe für alle neuen Flächen |
| `separate` | je Fläche eine Pflegegruppe |
| 1 Fläche | eine Pflegegruppe mit dieser Fläche |

`together` / `separate` werden **nicht** dauerhaft gespeichert.

## Begründung

Entspricht DL-004: Anzahl der Flächen und Art der gemeinsamen Begleitung sind getrennte Sachverhalte — ohne Verschmelzung von Flächen oder Historien.
