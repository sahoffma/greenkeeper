## Titel

Atomarer Onboarding-Abschluss per RPC

## Status

- ✅ Umgesetzt

## Priorität

- Hoch

## Beschreibung

Der reguläre Onboarding-Abschluss erfolgt **ausschließlich** über die Postgres-Funktion `complete_onboarding(payload jsonb)`:

1. Profil sperren (`FOR UPDATE`)
2. `onboarding_completed_at IS NULL` prüfen
3. keine aktiven Flächen vorhanden prüfen
4. Flächen anlegen
5. Pflegegruppen anlegen
6. Zuordnungen anlegen
7. `onboarding_completed_at` setzen

Bei jedem Fehler: vollständiger Rollback.

## Begründung

Client-seitiges Mehrfach-Speichern (Flächen, dann Profil) birgt Teilerfolge und Doppel-Onboarding. Eine RPC bildet die fachliche Transaktionsgrenze ab.

## Sicherheitsgrenze

- `SECURITY DEFINER` mit `search_path = public`
- `auth.uid()` Pflicht; keine Client-`user_id`
- Execute nur für Rolle `authenticated`
- RLS bleibt für direkte Client-Zugriffe auf `care_groups` / `care_group_areas` aktiv

## Duplicate-Schutz

- `onboarding_completed_at` gesperrt per Row-Lock
- Fehler `ONBOARDING_ALREADY_COMPLETED` bei Wiederholung
- Zusätzlich: `ACTIVE_AREAS_EXIST` wenn bereits Flächen vorhanden

## Auswirkungen

- Migration `20250725_onboarding_care_groups.sql`
- Client: `src/lib/onboardingPersist.ts` → `supabase.rpc('complete_onboarding')`
- Kein `createAreas()` mehr im regulären Onboarding-Abschluss
- Client-Guards: `ProtectedRoute` (Session + abgeschlossenes Onboarding), `OnboardingRoute` (Session, kein Wiederholen nach Abschluss), Profilstatus über `profiles.onboarding_completed_at`

## Client-Routing (2026-07-25, erweitert 2026-07-25)

### Authentifizierungsreise

| Schritt | Route | Guard |
|---------|-------|-------|
| Willkommen | `/` | `RootPage` — Gäste sehen Willkommensseite |
| Registrierung | `/register` | `GuestRoute` |
| Anmeldung | `/login` | `GuestRoute` |
| E-Mail bestätigen | `/email-bestaetigen` | `EmailConfirmationRoute` |
| Passwort vergessen | `/passwort-vergessen` | `GuestRoute` |
| Passwort zurücksetzen | `/passwort-zuruecksetzen` | `ResetPasswordRoute` |
| Garten-Onboarding | `/onboarding/*` | `OnboardingRoute` |
| App | `/`, `/journal`, `/area/:id`, … | `ProtectedRoute` |

**Nutzerreise:** Willkommen → Registrierung/Login → E-Mail-Bestätigung → Onboarding → Startseite.

E-Mail-Bestätigung über `user.email_confirmed_at` (Supabase). Keine parallele lokale Kennzeichnung.

Passwort-Reset über Supabase Recovery-Link → `/passwort-zuruecksetzen`.

### Weiterleitungslogik

| Zustand | Ziel |
|---------|------|
| Keine Session | `/` (Willkommen) bzw. `/login` für Onboarding-Einstieg ohne Session |
| Session, E-Mail unbestätigt | `/email-bestaetigen` |
| Session, E-Mail bestätigt, Onboarding offen | `/onboarding` |
| Session, E-Mail bestätigt, Onboarding abgeschlossen | Startseite / geschützte App (`/`, `/area/:id`, …) |
| Onboarding erneut nach Abschluss | Redirect `/` |

Während Session-, E-Mail- und Profilprüfung: `AuthLoadingScreen` — kein flackernder Falsch-Screen.
